# CPU EYE · CPU 可视化实验室

可部署为静态网站的 CPU 教学模拟器。零运行时依赖，程序解析与执行全部在浏览器内完成；代码不上传至编译服务器。

**在线使用：[CPU EYE · GitHub Pages](https://chinadongnet.github.io/cpu-eye-gpt6-codex/)**

打开网页即可选择示例、编辑 C++ 程序并运行，无需安装软件或登录。

## 本地使用

安装 Node.js 后，在项目目录运行：

```sh
npm run dev
```

打开 http://127.0.0.1:4173 。选择示例，点击运行或单步；也可编辑源码后点击「编译 / 重置」（Ctrl/Cmd + Enter）。指令左侧圆点可以设置断点。回退会恢复寄存器、内存、输出、标志位和调用栈。

```sh
npm test
npm run build
```

`dist/` 是直接维护的网页源码和部署目录，build 仅校验入口、静态资源、语法和部署配置，不生成或覆盖文件。无 npm 依赖，无需安装依赖。字体使用可选 Google Fonts；网络不可用时使用本地字体，不影响功能。

## 已实现

- x86 / x86-64 / ARM32 / ARM64 教学模型：对应寄存器名称、数量、位宽、标志位名称及伪汇编显示；切换模型会重新编译并复位。
- 可编辑 C++ 教学子集，词法分析 → 递归下降语法分析 → 带源码行号的中间指令 → 确定性虚拟机。
- 自动播放、速度调节、暂停、单条指令执行、指令断点、最近 600 步回退。
- 取指、译码、寄存器、ALU、内存模块高亮；操作描述、源码行、下一条指令与当前指令联动。
- 寄存器十六进制 / 十进制切换；变量地址、值、小端字节视图和递归调用栈。
- 七个示例：累加、递归阶乘、冒泡排序、斐波那契、位运算、最大公约数、类与成员变量。界面可一键校验 28 个示例/模型组合的返回值和输出；类示例还校验最终成员值。
- 运行错误带源码行号：越界、未初始化读取、除零、有符号溢出、assert 失败；限制源码 40,000 字符、指令 10,000 条、执行 50,000 步、递归 64 层、单数组 256 个元素、输出 20,000 字符。

## 支持的语法

支持 `int`、`bool`、定长整数数组（字面量长度）、int/bool 函数及递归；`if/else`、`for`、`while`、`break`、`continue`、`return`；整数运算、比较、短路逻辑、位运算、赋值、复合赋值、前后自增减；`cout` / `std::cout`、`endl` / `std::endl` 和 `assert`。main 需为无参数 int 函数。另支持下面说明的基础 `class` 数据成员子集。数组参数、全局变量、多变量声明、指针、引用、浮点、字符字面量、模板、完整标准库不在支持范围内，会报错。

### 基础 class 数据成员

支持在全局先定义类，再在函数中声明局部对象，通过 `.` 读写 `public` 的 `int`/`bool` 数据成员。例如：

```cpp
class A {
public:
    int x;
    int y;
};

int main() {
    A a;
    a.x = 1;
    a.y = 2;
    return 0;
}
```

内存面板显示 `a.x` 和 `a.y`，初始值标记为“未初始化”，两次成员赋值分别高亮对应单元。成员也可以用于表达式、标量函数参数、`cout`、`assert` 和复合赋值。成员地址指令显示对象基址加字节偏移；单步、回退与四种 CPU 模型均适用。

类默认访问权限为 `private`；可以声明 `public`、`private`、`protected` 分区，但函数外部访问只允许 `public` 成员。不存在的成员、非对象成员访问以及未初始化成员读取会报错。每个类支持 1–256 个单独声明的 int/bool 成员；教学布局按声明顺序为每个成员分配四字节，不等同于原生 C++ ABI。

当前不支持成员函数、构造/析构函数、继承、嵌套对象、成员数组、默认成员初始化、对象初始化/拷贝/整体运算、对象数组、对象参数或对象返回值。对象声明使用 `A a;`，然后逐成员赋值。

## 模型边界

这是**教学虚拟机及架构外观适配器**，不是完整 x86/ARM 指令集模拟器，也不是 GCC/Clang 编译服务。它不接受 ELF/PE 或机器码，不承诺原生 ISA、ABI、真实指令编码、流水线时序、缓存或性能一致性。界面明确标注“教学伪汇编”和“非周期精确模型”。四种模式执行同一套语义中间指令，架构主要区别在寄存器布局/位宽、地址显示、标志位名称和汇编风格。

所有 int 均为有符号 32 位；bool 规范化为 0/1，教学内存统一分配四字节槽。64 位寄存器用 BigInt 进行准确的补码格式化，但 C++ 算术仍为 int32。临时表达式值保存在教学操作数栈，前两个通用寄存器显示操作值，其余通用寄存器可能保持零。函数空间预留于调用时，变量声明指令负责初始化/标记其槽；退出内部词法作用域后保留槽便于观察，退出函数则回收其内存；main 结束保留最终快照。内存值不是原生 ABI 布局。

标志位按教学规则更新：算术结果更新零/符号位，加减法还计算进位/借位与溢出；ARM 减法进位按“无借位”解释。比较伪指令产生 0/1，再按该结果更新标志。不是各 ISA 对每条真实指令的精确标志行为。左移采用保守检查，拒绝负值左移或超过 INT32_MAX 的结果。

## 部署

### GitHub Pages

仓库通过 [Deploy GitHub Pages](https://github.com/chinadongnet/cpu-eye-gpt6-codex/actions/workflows/pages.yml) 工作流自动发布。推送到 `main` 或在 Actions 中手动运行工作流后，依次执行模拟器测试、静态文件校验，并仅上传 `dist/`。检查失败时不会部署新版本。

面向 `main` 的 PR 会运行独立的只读测试工作流；PR 检查不会发布网页。合并到 `main` 后才触发 Pages 自动部署。

仓库的 **Settings → Pages → Source** 设置为 **GitHub Actions**。工作流使用 GitHub 自动提供的令牌，无需添加密钥。前端资源和 ES module 导入均为相对路径，可直接运行于 `/cpu-eye-gpt6-codex/` 子路径。

Fork 后，在自己的仓库启用 GitHub Pages（选择 GitHub Actions）和 Actions，再手动执行工作流即可；访问地址以部署任务输出为准。

### 其他静态托管

将 `dist/` 的完整内容上传到任意支持 ES modules 的静态 HTTP(S) 托管服务即可，例如 Nginx 或静态网站服务。没有后端、数据库、API 密钥或编译服务器要求。不要直接双击 HTML 使用 file://，浏览器模块加载需要 HTTP(S)。当前 Sites 项目配置保存在 `.openai/hosting.json`。

项目同时提供 `cpu_load_program` / `cpu_step_program` 可选 WebMCP 工具，在支持 `document.modelContext` 的浏览器中注册；不支持的浏览器正常使用界面。此次环境无可用 WebMCP 验证上下文，因此未验证该可选 API 的浏览器集成。

## 后续扩展为真实 ISA 仿真

可在独立阶段接入沙箱化 Clang 交叉编译服务（四种 target），解析 ELF 与 DWARF 源码映射，再接入支持对应架构的机器码执行器。前端保留本项目的控制与状态视图，通过统一的 step/snapshot 接口连接执行后端。完整 C++ 编译和真实硬件仿真不属于本版实现。
